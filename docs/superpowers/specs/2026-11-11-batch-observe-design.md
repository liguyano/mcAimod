# 批量 `observe` 设计

## 目的与范围

Kurumi 允许在一条 `observe(scan, inventory, env)` 中向 AI 一次提交多个已有观察结果，减少阶段切换与模型调用。`observe(value)` 仍兼容；连续多行 `observe(...)` 不合并，第一行继续作为交还点。

## 方案选择

- **采纳 A：多参数调用。** 保持立即交还语义，一次返回多份结果；兼容现有 DSL。
- 未采纳 B：连续观察自动合并。会使既有脚本中 `observe()` 后的代码意外执行。

## 约束和行为

- Java 自制 DSL，不引入 Python 引擎或新依赖。
- 参数先按当前脚本表达式规则求值；返回时依顺序保留各值，尽量带上原始参数表达式作为标签，不覆盖 `success`、`entities` 等字段。
- 允许普通结构化数据与单张截图混用；截图通过已有独立多模态消息回传，其他结果通过文本观察回传。
- 任何参数求值或截图验证失败，按已有脚本失败机制报告错误，不提交部分观察。
- 当前执行器的单张截图通道不扩充为多张截图；多截图入参应有明确错误提示。
- 现有 `observe` 后面的操作只能由下一次 AI 阶段继续执行。

## 验证

- 解析器接受 `observe(a, b, c)` 与旧的 `observe(a)`。
- 执行器把结果在一次 `finishRun` 中回传，含参数名和完整数据；截图场景等待截图就绪后才交还。
- 更新模型用法文案与工具帮助；对零参数、超限、多截图、失败状态做回归测试。
