# mcAimod V0.1 设计规格（待确认）

日期：2026-10-21
目标：Minecraft Java Edition 26.2 / NeoForge / Java 25。
状态：设计待用户确认，尚未实现产品代码。

## 1. 目标与边界

先完成一个能根据**玩家当前状态及位置**进行自然对话的 AI Companion；架构允许下一阶段把上下文主体替换为 NPC。优先兼容单人游戏和安装本 Mod 的专用 NeoForge 服务器。

V0.1 包含：
- 服务端命令：`/ai <消息>`、`/ai clear`、`/ai status`、`/ai model list`、`/ai model use <配置名>`。
- 玩家游戏状态快照：维度、方块坐标、生物群系、游戏时间、天气、生命值、饥饿值、手持物品、装备、附近已加载实体及距离、关键状态效果。
- 模型提供者可切换：OpenAI 风格 Chat Completions 适配器，支持 OpenAI、DeepSeek 和 Ollama 的兼容接口，允许可配置 base URL、模型名、超时、密钥引用。
- 玩家 UUID 隔离最近 10 轮对话（仅内存）。模型切换不丢失记忆。
- 异步 HTTP 请求、超时、错误提示、限流与并发控制，不能阻塞游戏主线程。
- 明确提示模型游戏状态是某一时间点的快照；不允许模型直接操控世界或执行任意指令。

不包含：自定义聊天 GUI、语音、NPC 实体、NPC 自主行为、长期持久记忆、工具调用、流式逐字显示、直接更改游戏世界。

## 2. 官方基础

使用 NeoForgeMDKs/MDK-26.2-ModDevGradle 模板为基础，对应 Minecraft 26.2、Java 25。Mod ID 建议 `mcaimod`，包名 `com.liguyano.mcaimod`，首版 `0.1.0`。保留官方 Gradle Wrapper 和必要资源；不把外部服务密钥提交到仓库。

## 3. 模块与接口

1. `AIChatCommand`：注册指令、权限检查、输入长度限制、入口回执。
2. `GameContextCollector`：仅在服务器主线程读取状态，将游戏对象转换为纯 Java 不可变 `ActorSnapshot`；不加载远处区块、不把游戏对象传入异步线程。
3. `PromptBuilder`：按“固定行为约束 + 结构化世界快照 + 会话历史 + 本轮用户消息”创建模型消息；明确缺失字段，不虚构未知区块、玩家意图和未扫描实体。
4. `ConversationManager`：键为玩家 UUID，保存最后 10 轮完整问答；单个玩家每次最多一个在途请求，失败不加入历史；断线清理在途任务。
5. `ModelProvider`：异步 `chat(request, profile)`；V0.1 使用 OpenAI 风格 Chat Completions，`stream=false`，内部统一错误/回复类型。保留为 NPC 未来单独会话使用的通用接口。
6. `ModelProfileConfig`：服务端受控配置；普通玩家只能在管理员允许的配置中切换，API Key 通过环境变量或不纳入版本控制的本地配置读取，绝不通过网络包发给客户端或写入日志。
7. `AIChatService`：把命令、状态、记忆、模型连接组装；工作线程执行 I/O，成功或失败后调度回服务器线程反馈玩家。

## 4. 状态快照

`ActorSnapshot` 至少记录：actor ID/type、采集时间、dimension、整数坐标、biome、world time、weather（若适用）、health/maxHealth、food level、main/offhand、armor、status effects、附近实体的类型和距离。

- 默认扫描已加载区域的 16 格范围，至多最近 12 个实体，按距离排序并聚合，避免爆炸式上下文。
- 只传输对回答有帮助的数据；默认不包含整个背包、玩家 IP、服务器机密、其他人的聊天日志。
- 明确可开关精确坐标发送。若关闭，使用维度/生物群系/粗略位置。
- 对下界、末地等天气不适用的情形输出 `unknown` 或 `not_applicable`，不猜测。

## 5. 模型配置

多条 profile 可分别设置 `provider_type`、`base_url`、`model_id`、`api_key_env`、`request_timeout`、`max_output_tokens`、`enabled`。默认仅允许 HTTPS 远端地址；本机 Ollama 的 HTTP loopback 单独允许。兼容模式只依赖基本 `messages` 请求/文本回复，模型特有参数以后扩展。

## 6. 时序与线程

玩家发出命令 → 服务器验证权限、消息大小、模型 profile、限流 → 服务器主线程创建状态快照 → 读取前 10 轮历史并构建请求 → 工作线程通过 HTTP 请求模型 → 检查玩家会话/请求 ID 是否仍有效 → 切回服务器主线程显示回答并追加成功的问答。

失败路径：网络超时、401/429、响应格式错误、模型返回空文本、玩家下线；均只反馈可读错误、保留游戏运行，不能把失败伪装为模型回答。绝不记录密钥。

## 7. 测试与验收

- Java 单元测试：快照序列化、提示词构造（缺失字段/边界）、会话隔离与截断、模型回复解析、敏感配置不出现在日志。
- 用本地假模型 HTTP 服务测试成功、401、429、断网、超时、损坏 JSON。
- `gradlew test` / `gradlew build`，开发客户端 `gradlew runClient`；测试单人和专用服务器指令。
- 在两个玩家同时请求时验证隔离，不阻塞 Tick；服务端切换模型不会影响其他玩家未授权配置。
- 验收：`/ai 我现在在哪里` 可引用当前维度和生物群系；低血量时回复能结合生命值；历史能保持 10 轮；错误不崩溃；最终生成可安装 JAR。

## 8. 第二阶段的兼容性

状态获取从具体玩家升级为 `ActorContextSource`，分别用于玩家和 NPC；模型接口、提示词和会话管理复用。第一版不能为了 NPC 而加入复杂路径规划或可执行工具。
