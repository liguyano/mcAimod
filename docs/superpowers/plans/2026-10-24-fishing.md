# Kurumi Fishing v0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Kurumi 添加持续自动钓鱼，升级到 v0.4.0。

**Architecture:** 独立 FishingBridge tick 状态机、纯逻辑水域评分/咬钩判定、白名单脚本桥接与 Agent 提示词。

**Tech Stack:** Java 25, NeoForge 26.2.0.88, Minecraft 26.2, JUnit, Gradle.

**Spec:** `docs/superpowers/specs/2026-10-24-fishing-design.md`

## Global Constraints

- 钓鱼不能阻塞 Agent 对话；必须直接可停止。
- 仅在游戏客户端线程访问世界和鱼钩状态，禁止破坏方块的寻路。
- 不让脚本解释器执行任意 Java/Python。
- 继承尚未合并的多阶段 Agent PR #47；另开 v0.4.0 分支/PR。

## Review Focus

- 没有鱼竿/装备同步延迟时不会空手交互。
- 水坑、断层、深水中间和悬崖边缘不会当成安全岸边。
- 水漂飞行和回收时的负垂直速度不会误判为咬钩。
- 停止后不会在晚到的 tick 里重新抛竿。
- 离线、服务器拒绝或长时间不咬钩不会无限循环发送交互。
